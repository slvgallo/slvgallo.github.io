DESCRIPTION — Artwork Description Dataset Request
Read the attached HTML, CSS, and JavaScript files for the web-based artwork DESCRIPTION, and create an English-language artwork description dataset for it.
The purpose of this request is not merely to summarize the code accurately.
Read the structure of the code, the movements visible on screen, the transformation of the text, the timing of the edits, and the concepts suggested by the implementation. Develop the writing through your own interpretation of these elements.
Use only the attached code and your own understanding derived from it as your starting point.

Basic Approach
You do not need to produce one hundred conventional, neutral, or uniformly polished artwork descriptions.
The dataset may contain a mixture of:
	•	Texts that accurately describe how the artwork functions
	•	Texts that interpret the code structure in an original way
	•	Texts that develop conceptual ideas from technical behavior
	•	Texts that imagine possibilities not actually present in the artwork
	•	Texts that speculate about the artist’s intentions
	•	Critical writing
	•	Philosophical writing
	•	Poetic writing
	•	Semantically ambiguous writing
	•	Texts built primarily from abstract language
	•	Texts that may misread the artwork
	•	Texts that contradict one another
	•	Texts that affirm the artwork
	•	Texts that question or reject the artwork
	•	Texts that compare the code to another system, structure, organism, institution, or phenomenon
Prioritize variation in perspective, intensity, and interpretation across the entire dataset rather than factual accuracy or stylistic consistency.

How to Treat the Code
Read the attached code before writing.
However, you do not need to treat the code as the only correct interpretation of the artwork.
You may directly describe processes confirmed by the code. You may also interpret the code metaphorically, critically, philosophically, or fictionally.
You do not need to clearly distinguish between facts derived from the code and ideas developed through imagination. Both may coexist within the artwork descriptions.

The body text is continuously subjected to editing operations such as:

	•	Repositioning
Markov chains and the currently displayed text are used in the generation and transformation of the writing.

Afterward, the title is edited independently from the body text and gradually changes into other titles.
You do not need to limit yourself to this summary. Read the code and incorporate whatever elements you consider important.

Body Text Categories
Create twenty entries for each of the following five categories.
The total number of body-text entries must be one hundred.
These categories are loose organizational divisions. Some overlap between categories is acceptable.
overview
Write about the artwork as a whole.
You may explain what the artwork is, or define it as another kind of device, document, phenomenon, institution, body, memory, system, or condition.
editing
Focus on the act of editing.
You may discuss concrete operations such as selection, deletion, typing, correction, cutting, pasting, and movement.
You may also interpret these operations as generation, forgetting, destruction, repair, labor, imitation, violence, maintenance, or another process.
implementation
Write about the code, technology, data structure, and execution environment.
You may describe technical facts, or reinterpret the structure of the code conceptually, metaphorically, speculatively, or fictionally.
mutation
Write about transformation, collapse, reconstruction, repetition, bias, proliferation, contamination, recovery, or other forms of textual change.
You may discuss Markov chains or retraining, or describe them as evolution, infection, memory, decay, dreaming, inheritance, mutation, or misreading.
viewing
Write about reading, looking, waiting, overlooking, returning, remembering, or failing to return.
You may describe the viewer’s actual experience, or write from the perspective of an imaginary viewer, a future reader, a nonexistent audience, the browser, the title, or the text itself.

Diversity of the Writing
Do not make the twenty entries in each category into minor paraphrases of the same idea.
Intentional repetition is allowed.
When repeated phrases or structures seem meaningful to the artwork, you may deliberately use them.
Across the full set of one hundred body-text entries, create differences such as:
	•	Concrete / abstract
	•	Technical / poetic
	•	Short / long
	•	Clear / ambiguous
	•	Affirmative / negative
	•	Calm / provocative
	•	Explanatory / fragmentary
	•	Realistic / fictional
	•	Accurate / misreading
	•	Logical / associative
	•	Complete / open-ended
You do not need to distribute these qualities evenly.
Create whatever imbalance, emphasis, or stylistic bias AI_NAME considers appropriate for this artwork.

Language and Style
Write in English.
The style is unrestricted.
The dataset may include forms such as:
	•	Museum artwork descriptions
	•	Technical explanations
	•	Technical criticism
	•	Artwork analysis
	•	Manifestos
	•	Poetry
	•	Prose poetry
	•	Fictional specifications
	•	Error messages
	•	Proofreader’s notes
	•	Speech written from the system’s perspective
	•	Records written from the future
	•	Incomplete passages
	•	Semantically unstable writing
The style may change within a single entry.
Punctuation is unrestricted, provided each text remains valid inside a JSON string.

Body-Text Length
Each body-text entry should generally be 60–120 words.
Some shorter fragments and some entries longer than 120 words are acceptable.
The entries do not need to be uniform in length.
Aim for natural English rather than matching a specific character count.


Independence of Entries
Each entry should generally be capable of appearing as an independent paragraph.
However, expressions such as the following are not prohibited:
	•	As stated above
	•	The following section
	•	This paragraph
	•	The text above
	•	The later sentence
	•	The material that was just deleted
A reference may point to something that does not exist. A paragraph may refer incorrectly to another paragraph.
Because sentences in the artwork may be moved, deleted, and rearranged, broken references may be treated as part of the dataset.

Interpretation of the Artist and the Artwork
You may speculate about the artist’s intentions.
You may state those speculations as if they were factual.
You may invent intentions, motivations, histories, or contexts that the artist may never have considered.
Do not make every entry about the artist, however.
You may freely assign agency to different subjects, including:
	•	The artist
	•	The code
	•	The text
	•	The viewer
	•	The browser
	•	The editing operations
	•	The title
	•	The database
	•	The deleted material

Title Length
Title length is unrestricted.

The One Strong Constraint
Do not over-polish or over-normalize the dataset.
Do not make all one hundred body-text entries and all thirty title candidates converge into accurate, consistent, professional artwork descriptions and titles.
Deliberately preserve:
	•	Original interpretations
	•	Misreadings
	•	Conceptual leaps
	•	Contradictions
	•	Excessive certainty
	•	Ambiguity
	•	Unevenness
	•	Stylistic instability
